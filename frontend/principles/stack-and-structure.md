# Стек и структура

## Стек (ориентир)

| Слой | Технологии |
|---|---|
| Сборка | Vite, React, TypeScript, React Router |
| UI | Tailwind CSS, компоненты дизайн-системы в репозитории |
| Данные | TanStack Query, лёгкий стор (Zustand), состояние в URL (nuqs) |
| Формы | react-hook-form + zod |
| API | OpenAPI-схема бэкенда → генерация клиента и query-хуков |
| Тесты | Vitest, React Testing Library, MSW, Playwright |
| Качество | ESLint (flat config), typescript-eslint, Prettier, git-хуки |

Точные версии фиксируются в корневом `package.json` монорепо; обновление версии — отдельная
задача с обоснованием.

## Структура монорепо (pnpm)

```
frontend/
├── apps/web/                 # SPA-приложение
├── apps/<второе-приложение>/ # лендинг или второй клиент — отдельным приложением
├── packages/ui/              # дизайн-система: компоненты, токены, стили
├── packages/api-client/      # сгенерированный клиент + query-хуки
├── packages/shared/          # типы, утилиты, константы
├── packages/eslint-config/   # общие конфиги линтера
├── packages/tsconfig/        # базовые tsconfig
├── pnpm-workspace.yaml
└── package.json              # корневые скрипты и версии
```

## Слои внутри приложения

- `app/` — провайдеры, роутер, граница ошибок. Логики минимум.
- `routes/` — тонкий слой маршрутов: собрать фичи и сущности в экран.
- `features/` — одна папка = одна бизнес-возможность.
- `entities/` — доменные сущности, только переиспользуемое.
- `shared/` — UI-кит, утилиты, конфиг, тестовые утилиты; о фичах не знает.

Направление зависимостей — только в одну сторону:

```
shared → entities → features → routes/app
```

- **Импорт между соседними `features/*` запрещён.** Композиция — на уровне `routes/`.
  Проверяется правилом линтера, а не дисциплиной.
- **Barrel-файлы** (реэкспорт всего подряд) запрещены: ломают tree-shaking. Исключение —
  `features/<name>/index.ts` как публичный API фичи с явными экспортами.
- Сгенерированные файлы (API-клиент) руками не правятся и в UI напрямую не импортируются.
