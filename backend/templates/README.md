# Шаблоны сборки бэкенда

Готовые к копированию файлы, которые задают общие правила сборки для всех проектов
решения. Кладутся в корень каталога `backend/` проекта.

| Файл | Что задаёт | Что подставить под проект |
|---|---|---|
| `Directory.Build.props` | TFM, `Nullable`, `ImplicitUsings`, `TreatWarningsAsErrors`, стилевые правила в сборке, подключение анализаторов | Целевую версию .NET и набор анализаторов |
| `Directory.Packages.props` | Центральное управление версиями: все версии пакетов только здесь | Свой набор пакетов и версий (в шаблоне — примеры и общие) |
| `.globalconfig` | Уровни правил анализаторов: severity и отключения | Свои отключения — с причиной и записью в реестр проекта |
| `global.json` | Режим запуска тестов (Microsoft.Testing.Platform) | Версию SDK, если проект её фиксирует |
| `.gitignore` | Исключения сборки и файлы с реальными секретами | Пути к локальным файлам настроек и секретов |

## Порядок применения

1. Скопировать файлы в корень `backend/`.
2. Заменить примеры пакетов в `Directory.Packages.props` на фактические; версии писать
   точно, без диапазонов и `latest`.
3. В `.csproj` версии не указывать — только `<PackageReference Include="..." />`.
4. Проверить сборку: при `TreatWarningsAsErrors` она должна быть чистой.

## Оговорки

- **Отключения в `.globalconfig` — не универсальная истина.** В шаблоне лежат правила,
  отключённые в исходном проекте, с комментариями. Каждый проект решает сам; реестр
  отключённых правил ведётся в проекте.
- **`global.json` без версии SDK** фиксирует только режим тестового раннера. Если проект
  требует конкретный SDK — добавить поле `sdk`.
- **Файлы с секретами** не должны попадать в репозиторий: реальные значения — в переменных
  окружения или в закрытом `.gitignore` локальном файле; в репозитории остаются заглушки
  и примеры.
